# LEXACUBE credentials -- copy to the boot partition as lexacube.env during SD
# card prep, the same way dietpi.txt and dietpi-wifi.txt are placed. Bootstrap
# installs it to /etc/lexacube.env (mode 0600), which the generated
# lexacube.service and the repo-owned lexacube-analytics-upload.service both
# read via EnvironmentFile.
#
# This exists because these values cannot be defaulted or committed, yet a
# reflash without them yields a Pi that plays fine and records gameplay to its
# outbox but can never upload it. Placing the file at imaging time is what
# makes a rebuild reproducible.
#
# Fill in real values before copying. Never commit the filled-in copy.

# PostHog project key ("phc_..."). Write-only by design: it can send events,
# not read them, which is why it is acceptable on a device that travels to
# venues.
POSTHOG_API_KEY=

# REQUIRED for uploads. PostHog's free tier allows a single project, so
# several products share one event namespace and event names are not disjoint
# between them -- `session_started` means something different per product.
# Leave this blank and the uploader refuses to send rather than silently
# inflating another product's counts; there is no error for having got it
# wrong, only numbers that are wrong and are found much later.
#
# knockstrip.env.template.txt carries the same POSTHOG_API_KEY. If both games
# ever report to the same project, both need a distinct value here.
ANALYTICS_PRODUCT=lexacube
